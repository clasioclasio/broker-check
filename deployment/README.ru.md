# Обновление уже установленного сайта

Не запускайте `install.sh` повторно на работающем сайте.

Сначала загрузите обновлённые исходники в публичный GitHub-репозиторий.
В корне репозитория должна быть папка `deployment` с `update.sh`.
Затем на VPS, установленном нашим установщиком:

```bash
cd /root/broker-check
git pull --ff-only
bash deployment/update.sh https://github.com/clasioclasio/proverka.git
```

Скрипт собирает новую версию отдельно от работающей, сохраняет защищённую
резервную копию базы в `/var/backups/broker-check`, переключает API и публичные
файлы. Пароли, домен, сертификаты и действующая база не меняются.
Изменения схемы базы этим обновлением не выполняются.
При ошибке запуска API восстанавливаются предыдущие исходники.
Предыдущая версия и резервная копия базы автоматически не удаляются.

После обновления обе формы разрешают только одну заявку: повторная отправка
с тем же телефоном, WhatsApp или email отклоняется сервером. Браузер, в котором
уже подана заявка, показывает подтверждение вместо новой формы.
Смена браузера одновременно со сменой всех контактов не позволяет достоверно
установить, что это тот же человек: учётных записей клиентов на сайте нет.

# BROKER CHECK: перенос на собственный сервер

## Что включено

Полные исходники публичного сайта, админ-панели, API, схемы PostgreSQL,
общие библиотеки и зафиксированные зависимости. Сборка выполняется установщиком.
Архив не содержит реальные заявки, переписку, пароли, `.env`, историю Git,
служебную память агента, загруженные пользователем архивы и макеты другого проекта.

**Это новая установка с пустой базой.** Действующие заявки и другие данные
автоматически не переносятся. Если они нужны, переносите их отдельно защищённым
дампом, не через публичный GitHub.

## Требования

- Отдельный новый VPS: **Ubuntu 22.04/24.04 LTS** или **Debian 12/13**, архитектура **x86_64 / AMD64**.
- Рекомендуется 2 CPU, **4 ГБ RAM**, 15 ГБ свободного диска для сборки и базы.
- SSH-доступ и `root` либо `sudo`. Обычный VPS с systemd, не shared-хостинг.
- Свободные TCP-порты **80/443** с доступом из интернета. Порт API 3100
  занят только на `127.0.0.1`; открывать его извне не нужно.
- Домен уже куплен вами и настроен на этот сервер:
  `A` → публичный IPv4 сервера. Лишние A/AAAA-записи удалите.
  Если есть AAAA, она должна указывать на IPv6 того же сервера.
  На время установки выключите проксирование Cloudflare/CDN.
  Для `www.example.com` и `example.com` нужны отдельные настройки;
  установщик обслуживает **только введённое имя**.
- У регистратора CAA-записи должны разрешать выпуск сертификата Caddy
  (Let's Encrypt / ZeroSSL), либо CAA-записей не должно быть.
- Исходящий HTTPS для GitHub, npm, nodejs.org, ACME; DNS-запросы к 1.1.1.1.

Установщик настраивает сайт на домене, выпускает и автоматически продлевает
SSL через **Caddy**. Он **не покупает домен и не меняет DNS у регистратора**:
для этого нужен доступ к вашему регистратору. Если DNS неверен, он остановится
с подсказкой. Внешний firewall в панели хостинга тоже открывается вами.
Если UFW уже включён, установщик добавляет разрешения только для 80/443;
не включает UFW и не изменяет доступ по SSH.

## 1. Загрузите сайт на GitHub

1. Распакуйте единый архив `broker-check-autoinstall.zip` на компьютере.
2. Создайте свой **публичный** GitHub-репозиторий.
3. Загрузите **все распакованные файлы прямо в корень репозитория**.
   В архиве нет дополнительной внешней папки. В корне должны находиться
   **`install.sh`**, `package.json`, `pnpm-lock.yaml`,
   `pnpm-workspace.yaml`, каталоги `artifacts`, `lib`, `deployment`, `scripts`.
4. Не добавляйте реальные пароли, файлы окружения и дампы базы.

Не выкладывайте в публичный репозиторий `.env`, `/etc/broker-check/runtime.env`,
дампы БД, заявки и резервные копии. `.gitignore` защищает типовые имена,
но перед публикацией проверяйте содержимое сами.

## 2. Запустите установщик по SSH

Установщик **`install.sh` находится прямо в корне проекта**.
Основной сценарий — установка из публичного GitHub-репозитория.
После загрузки ВСЕХ файлов в GitHub выполните на сервере:

```bash
sudo apt-get update &&
sudo apt-get install -y git &&
git clone https://github.com/OWNER/REPO.git broker-check &&
cd broker-check &&
sudo bash install.sh
```

Замените OWNER/REPO на свой репозиторий. Команда предназначена для ещё
не скачанного проекта. Если папка `broker-check` уже существует и это ваш
ранее скачанный репозиторий, **не удаляйте её**, а обновите:

```bash
cd /root/broker-check &&
git pull --ff-only &&
sudo bash install.sh
```

Перед запуском убедитесь, что в GitHub появился корневой `install.sh` и
`deployment/install.sh`. В прежней версии репозитория установщика может не быть:
команда запуска не создаёт отсутствующие файлы. Не запускайте чужой `fix.sh`.

Также можно запустить `sudo bash install.sh` из распакованной полной папки
проекта на новом VPS. Скрипт сам находит соседние исходники, не требует
повторного скачивания репозитория и устанавливает именно эту версию.
Прямой запуск `sudo bash deployment/install.sh` тоже поддерживается.
Если отдельно скопирован только основной скрипт, он запросит GitHub-ссылку.
Не используйте `curl | bash`: нужен интерактивный терминал для скрытого ввода пароля.

Скрипт последовательно запросит:

1. Подтверждение установки на этот сервер.
2. HTTPS-ссылку на публичный GitHub-репозиторий, **только если исходников рядом нет**.
3. Домен без `https://` и без `/`: например `check.example.com`.
4. Email для SSL-сертификата, необязательно. Он передаётся удостоверяющему центру.
5. Новый логин администратора.
6. Новый пароль дважды; **ввод скрыт**, минимум 12 символов.

При отдельном запуске основного скрипта скачивается основная ветка репозитория.
При запуске из проекта используются уже скачанные исходники. Приватные репозитории, токены
в URL, ссылки на ZIP, ветки `/tree/...` и ARM-серверы не поддерживаются.
Используйте только свой проверенный репозиторий: его код выполняется при сборке
от отдельного непривилегированного пользователя.

## Что скрипт делает сам

- Устанавливает системные зависимости, PostgreSQL, Caddy, Node.js 22 и pnpm 10.26.1.
- Загружает официальный архив Node.js и проверяет SHA-256.
- Не заменяет системный Node.js, размещая свой в `/opt/broker-check-tools`.
- Использует скачанный проект (или скачивает репозиторий, если его рядом нет)
  и собирает сайт/API с зафиксированным lockfile.
- Создаёт пользователя `brokercheck`, новую роль и новую базу `brokercheck`.
  Доступ к базе — локальный Unix socket с peer-аутентификацией, без пароля БД.
- Создаёт таблицы из **актуальной схемы исходников**, в одной транзакции.
- Хранит новые учётные данные и случайный `SESSION_SECRET`
  в `/etc/broker-check/runtime.env`, файл доступен только root (`0600`).
  Файл **не shell-скрипт**, не выполняйте `source` для него.
- Запускает API на localhost, а публичную сборку отдаёт через Caddy.
  Исходники, конфигурация и секреты не доступны через веб-сервер.
- Настраивает автозапуск и перезапуск после сбоя через systemd.
- Проверяет API, страницу админки и действительный HTTPS-сертификат.

Системный сервис Caddy из пакета отключается, вместо него используется
отдельный `broker-check-web`. Другие существующие сайты не изменяются:
при занятых веб-портах или существующей установке скрипт отказывается продолжать.
Это **не установщик обновлений**.

## Адреса и команды обслуживания

```text
https://ВАШ-ДОМЕН/
https://ВАШ-ДОМЕН/admin
```

```bash
sudo systemctl status broker-check-api broker-check-web --no-pager
sudo journalctl -u broker-check-api -u broker-check-web -n 100 --no-pager
sudo systemctl restart broker-check-api
sudo systemctl reload broker-check-web
```

Пароли не показывайте в чате или скриншотах. Для смены админ-пароля
отредактируйте `ADMIN_PASSWORD` в защищённом файле через
`sudo nano /etc/broker-check/runtime.env`, сохраняя двойные кавычки и
экранирование `\` и `"`; затем перезапустите `broker-check-api`.
После перезапуска администраторы входят повторно: сеансы сейчас хранятся в памяти.

## Резервные копии

Не храните дампы в `/var/www` или GitHub. Пример ручной защищённой копии:

```bash
sudo install -d -m 700 /var/backups/broker-check
sudo sh -c 'umask 077; runuser -u postgres -- pg_dump -Fc brokercheck > /var/backups/broker-check/database-$(date +%F-%H%M%S).dump'
```

Отдельно сохраните `/etc/broker-check/runtime.env` в защищённом хранилище.
Автоматический график резервного копирования в установщик не входит.
Перед обновлениями делайте резервную копию БД и конфигурации.

## Если установка остановилась

Файлы и база автоматически не удаляются. Прочитайте сообщение и журнал.
Не удаляйте базу и каталоги, если в них уже появились реальные данные.
Скрипт намеренно не запускается повторно поверх существующей установки.
Если первый запуск прервался до создания каталогов, исправьте DNS и запустите снова.
Если каталоги/база уже созданы, нужно закончить настройку вручную
либо использовать другой чистый сервер; не удаляйте их вслепую.

Если HTTPS не появился сразу, Caddy продолжает выпуск сертификата в фоне.
Исправьте DNS, CAA и доступ к TCP 80/443, затем проверьте
`sudo journalctl -u broker-check-web -n 100 --no-pager`.
При необходимости перезапустите `broker-check-web`; повторная установка не нужна.

## Проверка перед передачей клиентам

Полная установка требует реального чистого VPS и домена. В среде разработки
проверены синтаксис и безопасные функции скрипта, сборка проекта и архив.
Это не заменяет пробный запуск на вашем сервере.
После установки проверьте вход в `/admin`, тестовую заявку, её появление в панели
и отправку сообщения. Не выдавайте ручную отправку отчёта в WhatsApp за автоматическую:
установка этого не меняет.
